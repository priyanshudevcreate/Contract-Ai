# Vercel Deployment Guide for ContractGPT

## Prerequisites

1. A Vercel account (https://vercel.com)
2. GitHub/GitLab repository with your project
3. Vercel CLI installed (optional): `npm install -g vercel`

## Deployment Steps

### 1. Connect Repository to Vercel

1. Go to https://vercel.com/dashboard
2. Click "New Project"
3. Import your GitHub repository
4. Select the repository containing this project

### 2. Configure Build Settings

Vercel should automatically detect the project settings, but ensure:

- **Framework Preset**: Vite
- **Root Directory**: `./` (or leave empty)
- **Build Command**: `npm run vercel-build` (or `vite build`)
- **Output Directory**: `dist`

### 3. Environment Variables

Set the following environment variables in your Vercel dashboard:

#### Required Variables

```bash
# JWT Configuration (CRITICAL - Generate strong secrets)
JWT_SECRET=your-super-secure-jwt-secret-key-minimum-32-characters
JWT_EXPIRES_IN=7d

# Database (SQLite will be created automatically)
NODE_ENV=production

# Frontend URL (will be auto-generated by Vercel)
FRONTEND_URL=https://your-project-name.vercel.app

# File Upload Configuration
MAX_FILE_SIZE=10485760
```

#### Optional Variables

```bash
# If using external database instead of SQLite
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/contractgpt

# API Rate Limiting
RATE_LIMIT_WINDOW_MS=900000
RATE_LIMIT_MAX_REQUESTS=100
```

### 4. Deploy

1. Push your code to your connected repository
2. Vercel will automatically build and deploy
3. Your app will be available at `https://your-project-name.vercel.app`

## Important Notes

### Database Considerations

- **SQLite**: Works on Vercel but data is ephemeral (resets on each deployment)
- **Recommended**: Use a persistent database like MongoDB Atlas, PlanetScale, or Supabase for production

### File Upload Limitations

- Vercel serverless functions have a 50MB payload limit
- Files are stored in memory during processing
- For persistent file storage, consider using:
  - AWS S3
  - Vercel Blob Storage
  - Cloudinary

### Python Bot Integration

The Python legal analysis bot cannot run directly on Vercel serverless functions. Consider:

1. **Separate Python API**: Deploy the Python bot on:
   - Railway
   - Render
   - Heroku
   - Google Cloud Run

2. **Alternative Solutions**:
   - Convert Python logic to Node.js
   - Use OpenAI API directly from Node.js
   - Deploy Python bot as a microservice

## Frontend Configuration

The frontend automatically detects the environment and uses:
- Development: `http://localhost:3001` for API calls
- Production: `/api/*` (proxied to serverless functions)

## Monitoring and Logs

- View deployment logs in Vercel dashboard
- Function logs are available in the "Functions" tab
- Set up error monitoring with Sentry or similar tools

## Database Migration

If you need to migrate from SQLite to a persistent database:

1. Export existing data from SQLite
2. Set up MongoDB Atlas or similar
3. Update `MONGODB_URI` environment variable
4. Update database.js to use MongoDB instead of SQLite

## Troubleshooting

### Common Issues

1. **Build Fails**
   - Check if all dependencies are in package.json
   - Verify build command in vercel.json

2. **API Routes Don't Work**
   - Ensure api/index.js exports the Express app
   - Check environment variables are set

3. **CORS Issues**
   - Verify FRONTEND_URL environment variable
   - Check CORS configuration in api/index.js

4. **Database Errors**
   - SQLite files are ephemeral on Vercel
   - Consider using a persistent database

## Security Considerations

1. **JWT Secret**: Use a strong, unique secret (minimum 32 characters)
2. **Environment Variables**: Never commit secrets to version control
3. **HTTPS**: Vercel provides HTTPS by default
4. **Rate Limiting**: Configured in the API to prevent abuse
5. **Input Validation**: All user inputs are validated

## Performance Optimization

1. **Static Assets**: Served via Vercel's CDN
2. **Code Splitting**: Vite automatically splits code for optimal loading
3. **Compression**: Vercel automatically compresses responses
4. **Caching**: Static assets are cached with optimal headers
